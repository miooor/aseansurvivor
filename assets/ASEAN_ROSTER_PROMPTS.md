# ASEAN roster art provenance

These are original fictional adult game characters generated with the built-in image tool for issue #17 under the authored roster specification. This file records art production, not cultural approval. The seven silhouettes, occupations and portrayal limits come from `docs/asean-hero-concepts.md`; the implementation authorization is `docs/asean-roster-spec.md`.

## Sources and exact prompts

The initial style reference was the repository's `assets/survivors-atlas.png`, inspected before generation. Only its warm painted rendering, readable outline and adult game proportions were requested. The shared portrait atlas established the seven new identities; every motion/skills sheet used that portrait atlas as its identity/style reference. No third-party character artwork, melody or decorative motif was supplied.

The complete, verbatim tool prompts, generated source paths, final destination paths, and targeted cleanup prompts are in [generation.json](../docs/evidence/roster-art/generation.json). All calls used `transparent_background: true`. One call generated each asset, with up to three independent calls queued together; two additional built-in edits replaced noisy background versions of Asha motion and Vanna skills. Accepted PNGs are the tool's original pixels, copied without cropping, resizing or procedural repainting. Discarded initial variants remain at the recorded generated paths and are not runtime assets.

## Atlas contract

- `roster-portraits.png/.webp`: four columns, two rows, row-major Asha/Mira/Dani/Vanna/Keo/Nadi/Lia/empty. Source dimensions 1774×887. Use rounded cell boundaries because tool output dimensions differ from the requested dimensions.
- Fourteen `<id>-motion.png/.webp` and `<id>-skills.png/.webp` sheets: eight columns and eight rows, exactly 64 full-body poses per sheet. Source dimensions 1254×1254. Use the measured frame rectangles in `src/content/roster-frames.js`; generated row/column gutters differ from equal fractions. No source resampling was performed.
- Column order: E, SE, S, SW, W, NW, N, NE. The final three columns include actual back-facing silhouettes, not flipped front views.
- Motion rows 0–3: left step, passing, right step, opposite passing. Motion rows 4–7: basic ready, windup, extension, recovery.
- Skills rows 0/1, 2/3, 4/5, 6/7: Q/E/F/R windup and release. No labels, national flags, grid lines, ground plane or shadow are baked into these atlases.
- Requested sole pivot was at 85% cell height, with padding. Actual measured body bounds and any deviations are recorded in conformance/evidence, and must govern renderer framing. A request in a prompt is not a measured result.

## Encoding and repeatable verification

Run the asset-only check in the existing pinned Pillow container:

```sh
docker run --rm --entrypoint python -v "$PWD:/app" -w /app asean-astrocade-assets:latest scripts/measure-roster-frames.py
docker run --rm --entrypoint python -v "$PWD:/app" -w /app asean-astrocade-assets:latest scripts/check-roster-art.py --encode --frames docs/evidence/roster-art/frame-manifest.json
```

The image is built from `astrocade/assets.Dockerfile` (Python 3.12, Pillow 11.3.0). The script retains the PNG source, encodes same-size WebP at quality 85/method 4, verifies exact alpha and visible RGB RMS below 8/255 over opaque black, records SHA-256/bytes/decoded memory, checks every cell for content, detects repeated exact pose pixels, and reports visible frame-edge clipping. Pixel checks do not prove anatomical/directional quality; the complete sheets were also visually inspected. Raw transparent previews can expose bright RGB values stored under near-zero alpha. The opaque-dark diagnostic demonstrates visible compositing without changing project source pixels.

The sole runtime source in this art package is the generated `src/content/roster-frames.js` data module, explicitly assigned during integration. No CDN upload or other runtime code is owned here. The shared foundation loads the WebPs through its explicit manifest and prepares only the selected motion/skills pair. Browser progression, touch interaction, loading races, physical-phone performance, balance and local cultural/name review belong to integration verification, not these source-image checks.

The original equal-grid check is retained as `equal-grid-conformance.json` (189 failures). Measured gutters replace that invalid framing contract. Two Mira cells initially lacked a padding row because an exclusive frame end assigned the single empty gutter row to the next frame; both rectangles now include that shared empty row. No body pixels overlap at alpha >=32. The first measured report remains as `measured-frames-first32.json` (two failures); the final measured report has zero failures.

The unused eighth portrait cell contains no figure or alpha >=32 content. It retains 4,049 near-transparent pixels at alpha 1/255 from image-tool segmentation. Exact zero-alpha emptiness failed the initial diagnostic. The accepted observable boundary checks both black and white composites against flat backgrounds with maximum error <=1/255 per channel; the renderer uses only the seven populated indices. This does not change the >=32 body-containment gate.

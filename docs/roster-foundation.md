# Roster foundation contracts

Ticket #18 under [the roster spec](asean-roster-spec.md). Shared registration and art/loading seams support the seven pack implementations; the empty installer modules deliberately register no playable placeholder kits.

Each `src/game/heroes/<id>.js` exports `installAsha(api)`, `installMira(api)`, `installDani(api)`, `installVanna(api)`, `installKeo(api)`, `installNadi(api)` or `installLia(api)`. Runtime invokes these after `installHeroes`, before `installIdentities` and equipment. Register `HEROES[id]` (including numeric rank-one `basicDamage`, complete skills and `identity`), five `CAST[id]` functions, useful `AUTO[id]` predicates and `EVOS[id]=[]`. Identity metadata is `{title,name,color,max,key,loop,hint,ready}`. Basic/Q/E/F/R pose durations are already in `skillPoses`; the common wrapper handles successful audio, pose and exactly one cast hook. A rejected CAST must return literal `false` before changing state. Do not wrap or call CAST again for delayed effects.

New transient state belongs under `g.roster`, initialized to `{}` before newGame hooks, independently of `g.identity` and `g.sea`. A pack may set `g.identity.detail` (signature value text) and `g.identity.ready` (boolean override); otherwise existing charge/max behavior applies. Maintain bounded simulation-time state and cleanup on newGame, cleanup and both raid transitions, synchronizing before CAST as well as update. The pack owns any narrow transition helper it actually reuses.

The installer API includes `safePoint(x,y,r)`, `moveOnMap(fromX,fromY,toX,toY,r)`, `walkable(x,y,r)` and `clearLine(a,b,r)`, automatically using the active world or the existing circular `raid.ARENA` with radius padding. Raid placement stays near 60000-unit arena coordinates; segments between valid padded points are clear because the arena is convex and has no internal blockers. Outdoor helpers retain the world implementation. Runtime movement and Nok’s raid-only leap endpoint use these same helpers. It also includes `nearest`, `each`, `hit`, `aimDir`, `rm`, registries and HOOKS. Projectile `hitOptions` is spread into `hit` before `origin`/`dot`; use e.g. `{hero:'asha',slot:0}` and observe `HOOKS.hit(e,options)` for an accepted hit after oil-slip rejection. `onHit` still describes collision, including rejected damage, and must not serve tickets. Item-origin effects remain separate.

`src/game/geometry.js` owns the pure `inDirectedLine(enemy,x,y,ax,ay,length,width)` predicate for normalized captured directions. Width is the full lane width; inclusive longitudinal and lateral bounds expand by enemy radius. Mira/Dani/Nadi/Lia retain their own dimensions, damage, knockback, placement and scheduling.

Keo E projectile `hitOptions.crosswindDrumActive` captures pre-cast Drum eligibility. The equipment damage callback uses that explicit boolean for those bolts; other hits retain live Drum evaluation. This prevents E's own after-cast activation from retroactively boosting its landing, while retaining already active Drum and all other ordinary modifiers.

`HOOKS.absorb` receives damage after all `HOOKS.hurt` mitigation/parry hooks and before lethal hooks; a numeric return replaces remaining damage, clamped nonnegative. Dani keeps its own bounded HP/expiry shield, leaving `p.shield` timed immunity untouched. Damage hooks report applied HP damage. Dash `hitOptions` may override the legacy knockback (Lia should supply `kb:[0,0]` for her authored damage-only E). Collision-corrected dash position is used for dash hits, effects and fire; raid bounds apply before dash hits too. `p.normalMove` is null for a dash or no input, otherwise `{x,y,dx,dy,dt}` records that step's corrected ordinary movement. Packs must also compare their last observed position with the movement origin `(x-dx,y-dy)` to reject synthetic coordinate jumps/teleports, and exclude any dash at the cast/catch boundary.

Each `src/scenes/heroes/<id>.ts` exports `drawAsha(scene,g)` etc, dispatched for the matching hero. `scene.floor`, `scene.effects`, `scene.circle(graphics,x,y,r,color,alpha?,line?)` and `scene.color(css?)` are public drawing primitives. The scene module owns persistent geometry drawing only; simulation remains in the installer. Type `g.roster` locally using pack-owned interfaces, not by modifying shared runtime types for every kit.

`src/content/hero-art.js` is the explicit static manifest: `motion`, `skills`, optional measured motion `rows`, `idleIndex` for the original five, `idleRow:7` for new recovery poses, `portraitIndex`, display `size`, `originY` and `idleOriginY`. Original movement/idle origins remain .95/.85; new recovery and motion origins default to .99, matching the art owner’s reported near-bottom sole placement. Final per-hero measured alignment belongs to art integration. Existing Hakim gutters and five-direction idle rows remain intact. New 8×8 motion and skill WebPs are selected-only; the seven-portrait 4×2 WebP is shared. `scene.prepareHero(id):Promise<void>` loads/registers the selected pair and rejects unknown, failed, superseded or shut-down requests. `scene.isHeroPrepared(id)` checks both real frame sets. Synchronous `runtime.newGame` requires prepared assets. Fixtures must await the explicit scene method before direct starts. UI Start waits on the same boundary; retry/stage continuation reuse prepared assets. Loading serializes selections, retains at most current plus incoming pair, and releases superseded or inactive textures.

Flags are the eleven unmodified 4:3 SVGs from flag-icons commit `ac7e0eb3259eb62aa6100c435607e2fe03896a97`; license/provenance are in `assets/flags/`. Trusted raw SVG imports become encoded data URL images. Name surfaces preserve `.hero-name` separately from `.hero-flag` and country text; no emoji or third-party runtime fetches.

Browser acceptance lives at `/tests/roster-foundation.html`. It covers original-five real starts, flags, basic metadata, first level-up, rejected cooldowns, retries, selected loading and rapid preparations. `docs/evidence/roster-foundation/red.json` records the preimplementation failure. Pack behavior, all-twelve integration, new-art visual validation and final export remain separate dependent acceptance scopes.

The loader validates actual texture presence on completion, including image-decode failure after an HTTP-200 HTML response (Vite’s SPA fallback). `loaderror` alone cannot prove both images decoded. The browser fixture temporarily redirects only the requested `hero-motion-rempit` URL at the public Phaser loader boundary, delegates the real loading pipeline, restores it in `finally`, and verifies current-run preservation, partial-pair removal, visible Retry and successful real Start. Earlier module-URL fault experiments were inconclusive; the retained loader-red report includes the actual failed URL and is the source-fix evidence.

The foundation includes the art ticket’s exact validated 896-frame map (SHA-256 `6d1341cfd9fedf22f87733a0464aa0d89d7905e878170daaf2b4feb2d397b2b3`), copied without modification with parent authorization; ticket #17 owns its measurement script/provenance.
